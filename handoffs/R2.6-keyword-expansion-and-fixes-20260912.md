### Fix 2: Phase-aware review routing (planner.mjs)

Implement A8-symmetric rule. Implementation:

```text
1. If input matches /^review\s+/i AND phase ∈ {review, verification}:
   - Strip the "review " prefix from the input.
   - Route the remainder through the normal cluster scoring (scanTokens + scoreClusters).
   - If the remainder produces AMBIGUOUS, return AMBIGUOUS (do not silently pick a winner).
2. If input matches /^review\s+/i AND phase ∉ {review, verification}:
   - Return NO_MATCH immediately (do not strip prefix, do not score).
3. If input does NOT match /^review\s+/i:
   - Normal phase-aware routing (unchanged).
```

This replaces the old A8 mechanism (which only added T5 trigger terms in review/verification but never suppressed scoring elsewhere).

Boundary case: `review frontend security code` — strip prefix → `frontend security code` → T4 and T5 may tie → AMBIGUOUS. Do not pick.

### Fix 3: Suggestion rule (planner.mjs)

Replace the current Levenshtein suggestion logic with:

```text
Allow suggestion if:
  levenshtein(token.toLowerCase(), keyword.toLowerCase()) <= 2
  AND max(longestCommonPrefix(token, keyword), longestCommonSuffix(token, keyword)) >= 3
```

This allows `frontned → frontend` (prefix `front` = 5 chars) while rejecting `form → from` (prefix `fo` = 2 chars).
