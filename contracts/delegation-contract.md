# YY v1.1 delegation contract — revision 1

`contracts/delegation.schema.json` is the single field declaration. `scripts/build-delegation-contract.mjs` emits browser-compatible data; `--check` rejects drift. `scripts/lib/delegation-contract.mjs` exports `assertContract(name, value)` and `canonicalJson(value)` without filesystem, execution or state access. Node and webview share this module. Python consumes the JSON declaration, not a second schema. Runtime business invariants remain in their existing owners and the task-specific modules.

## Frozen compatibility mapping

Execution modes remain HOST_NATIVE / EXTERNAL_PROVIDER / BRIEF_ONLY. Delegation choice is independent; MANUAL_HANDOFF is not evidence of execution. PREVIEW has no business writes, registered=false. Local PREPARE registers the trusted package through the existing task store. No additional MCP write operations. M1 remains exact-six. The V2 resource operation may add a closed SourceReadRequest to the existing task decision, subject to T10 approved argument checks, with no new tool.

Task/workflow IDs reuse their existing validation domains. New logical IDs are opaque and never filesystem paths. Source reads resolve only current authorized logical declarations. Native method elision requires matching source identity, never a same-name skill. New unknown fields and versions fail closed at the shared schema boundary.

The handoff substate does not replace existing task states: AWAITING_RESULT waits for host, RESULT_RECEIVED and VALIDATING do not complete a task, ACCEPTED permits local resume only after trusted checker and state-version CAS, REWORK_REQUIRED preserves the same task. Imported PASS is self-report. Accepted manual output does not set executed=true or create a Receipt v2 record. Methodology application remains UNVERIFIED, C5 deferred.

Digests use exact original bytes for files and rendered UTF-8 text. Structured semantic cores use sorted-key JSON primitives and safe integers (no floats, undefined or timestamps in the semantic core). Exclude a digest field from its own digest. ReturnEnvelope fixtures and ValidationResult share the same return digest and artifact list. UTF-8 page hashes differ from raw full-source hashes. Public authority identity is generated by the existing release builders and is not hand-written.

## Boundary tests

Shared fixtures are synthetic, not execution or Web evidence. Node and Python must accept the same eight fixtures; negative checks cover unknown keys, nested permission injection, draft versions, unsafe paths, ID boundaries and zero read limits. Real browser/backend and ChatGPT Web evidence belongs to T14/T19.

C02 usage records use only the closed `UsageObservation` definition: status, observable_scope, usage_refs, units (nullable input_tokens/output_tokens/model_calls/read_bytes), and unobservable. Missing observations remain null, never zero or fabricated charges. No billed-cost calculator is introduced. T04/T09 own its production observation, T12 projects usage_status.

C08 is development evidence, not a product contract. Reuse the per-task report shape demonstrated by baseline/T01-report.json: task_id, base_snapshot, contract_revision/schema_digest, changed_files with classification/consumer/sha256, test_commands with command/exit_code/stdout_ref, plus independent review file and rollback/drift references at T18. The execution-ledger is explicitly development-only. No second runtime audit store.
