# TT 自进化架构决策（architecture）

> 来源：tgent v1.x 对齐 arXiv:2606.18837（Skill-MAS）后的取舍纪律，v2.0 保留为方法论原则。

## 原则（取舍后执行纪律）

1. **不采用 Ground-truth label 与 Benchmark 数据集**：TT 坚持"**真实运行证据链**"路线（git log / 数据库实测 / 真实 HTTP / 测试实跑 / grep 审计 / 用户验收），不依赖标准答案与离线评测集。理由：真实工程无 ground-truth，且独立实证证据链可直接复用为 LLM-as-judge 输入——补上论文自认的短板。
2. **不采用 K=3/K=5 多轨迹采样**：现有"返工直到通过 + 跨平台切换"流程已够用，K 次重复采样冗余。验收以"单遍真实运行证据 + 不过则切平台重做"为准。
3. **高价值任务判定（宁可多批判、不漏反哺案例）**：深度批判池 = 不符合低价值条件的全部任务。判定 p>0.15 一律纳入深度批判池；"低价值"仅指证据链完整、零失败、无边界争议、一次通过且无批判反哺价值的小任务。
4. **跨任务证据包（列入优化方案）**：每轮结束把多个 task 的批判证据跨任务合成，提炼系统性编排原则写入 CHANGELOG 并反哺下一轮任务要求；禁止把单任务个例写成 skill 规则。
5. **保留八步脚手架、局部改写**：修改本 skill 时严格保留 0~8 八步框架，只针对被证据指向的模块局部改写，每次修改必须能抽象成通用编排原则（非某项目特例），改后跑 `validate-structure.mjs`。

## 证据分级标签（去幻觉）

每条需求/结论标来源：`用户原话` / `竞品实抓URL` / `技术文档` / `推演`；无证据标 `[待补充]` 或 `[推演]`，禁编造。

## 版本与协议解耦

- skill 版本（SKILL.md version）与 TTHP 协议版本各自独立演进。
- 外部对比自批判：检索最新 MAS/自进化研究，取可迁移原则（证据回写/脚手架保护），弃不适配项（K 轨迹/ground-truth）。
