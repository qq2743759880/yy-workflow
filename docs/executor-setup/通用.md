## 边界（先读）

- 本向导（`scripts/executor-setup.mjs`）与本文档**绝不读取/写入任何凭据文件**，绝不写宿主
  配置文件；认证一律由用户本人在官方 CLI 内完成。
- Windows 上不做 mklink/管理员操作；探测只用 PATH（where）。

## 通用方法论（任何 CLI 都适用的三步）

1. **安装与认证**：按该 CLI 官方渠道安装，并在用户自己的终端完成登录/认证。
2. **presence 自检**（存在性档，零配额消耗）：
   ```bash
   node scripts/executor-setup.mjs --probe presence            # 六目标全测
   node scripts/executor-setup.mjs --probe presence --json     # 机读
   ```
   输出 `PRESENCE_YES/NO` 与登记的非交互形态。**存在 ≠ 可用**，本档永不回答可用性。
3. **roundtrip 自检**（真实往返档，每次消耗一次 API 配额，必须显式指名）：
   ```bash
   node scripts/executor-setup.mjs --probe roundtrip --cli <name>
   ```
   输出 `ROUNDTRIP_OK / ROUNDTRIP_FAIL / ROUNDTRIP_TIMEOUT / SKIP`。brief 是良性的
   "回复 OK"，沙箱 cwd，不执行任何仓库代码。SKIP 的原因（无非交互形态/未编码/不存在）
   原样呈现在输出里，不猜。

## 选择与持久化

- 交互模式选 B（本机 CLI 子代理，默认）→ 选择落 `<workspace>/.tt-state/executor.json`
  （withLock 写，双会话不互踩）；读取顺序 `--executor` 显式 > executor.json > 交互询问。
- 非交互环境：`node scripts/executor-setup.mjs --non-interactive --executor <cli> --save`。
- 交接任务（schema 化）：`node scripts/executor-setup.mjs --handoff --plan-id <id> --task-id <id>`，
  回填报告用 `node scripts/summary-read.mjs --validate-handoff <reports 目录>` 机验。
