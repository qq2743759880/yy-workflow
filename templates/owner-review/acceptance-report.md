# 验收报告 · owner 审核指引

> 用途：任务完工后，你（owner）独立实证验收——不采信完工报告，跑测试/真实请求逐个复现证据。

## 这个 gate 在审什么
是不是真的做完了——每个验收断言是否真实通过、有无资产调用证据、有无遗留问题。全部 PASS 才解锁下游。

## 看哪几个字段
对照 `templates/completion-report.md`，重点看：
- **GWT 逐条自查** 段：每条 Given-When-Then 的结果与证据（命令输出/文件路径/commit）
- **资产消费证据（硬约束）** 段：是否具名列出实际调用资产，未调用是否如实写「未调用外部资产」
- **批判承接核对** 段：命中 C-xx 是否逐条给出完成证据
- **遗留问题 / 待确认** 段：是否有未闭环项

## PASS-FAIL 判断口径
- **PASS**：你独立复现了 GWT 证据、资产消费属实、无遗留阻断项——说「验收通过」。
- **FAIL**：证据不可复现、资产消费造假、遗留未闭环——打回，不通过不得解锁下游。

## 常见坑
- 只信报告不复现 → 验收偷懒，翻车大多发生在这，下游基于假验收继续。
- 资产消费造假或空写 → 透明化失败，看不出到底用了什么。
