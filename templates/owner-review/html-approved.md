# HTML APPROVED · owner 审核指引（Gate A）

> 用途：前端页面开工前，HTML 原型必须先由你（owner）审美签收，才准写框架代码。

## 这个 gate 在审什么
审美方向对不对——这个 HTML 原型（页面视觉/布局/交互）是不是你要的样子。此关过了才允许写框架代码。

## 看哪几个字段
对照前端页面 HTML 原型产物，重点看：
- 页面视觉：布局、配色、间距是否符合你的审美预期
- 交互状态：正常/空/错误/边界（loading、无数据、报错）是否有交代
- 响应式：不同屏宽下是否可接受（如适用）

术语提示：Gate A=「前端审美签收门」，通过后才能进入框架实现。

## PASS-FAIL 判断口径
- **PASS**：审美方向你认可、交互态交代清楚——明确说「APPROVED」。
- **FAIL**：方向不对、交互残缺——退回改原型，未 APPROVED 不得写框架。

## 常见坑
- 没 APPROVED 就写框架 → 返工成本高一个量级，框架按错原型写。
- 只看截图不看交互 → 漏掉空态/错误态，上线后体验差。
