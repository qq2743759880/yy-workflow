# task14｜协作记录增量游标与状态解释（M2）

状态：后续分门，未获实施授权。依据：PRD UJ-02/05、§12–13；AT-17–18 的回读面。

## 交付与关联

- 交付 proposal/review/disposition 的版本化增量读取，支持网页断线后继续、游标过期后明确重新取快照；页面文字区分“建议”“已采纳”“待 Owner 签收”。
- 前置：task12/13；后置：task15/20。选型：在唯一 YY 事件/版本权威上建游标，避免网页维护自有任务状态副本。
- 候选 seam：现有状态版本/namespace 读取与生产 M read 工具；事件保留期和错误语义在阶段 5 冻结。

## GWT 验收

1. Given 网页断线前持有游标，When Codex 处理提案后恢复，Then只读到同一 workflow 下新增的 disposition/review，顺序和版本可核对。
2. Given 游标过期或底层版本迁移，When 恢复读取，Then返回具名重新取快照指令，不混接不同版本的增量。
3. Given 同时存在提案和待审批执行请求，When 展示状态，Then建议/审阅/Owner 授权分别标识，不把网页确认渲染为执行许可。
