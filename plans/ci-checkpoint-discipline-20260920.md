# CI 检查点纪律（S5 裁决防护 #4 落地）— 2026-09-20

来源：`plans/decision-s5-p0-semantics-20260920.md` 选择 2 连锁问题 #1 的防护。

## 纪律

1. **CI（`scripts/ci.mjs`，含 S1-S6 与 S5 P0 硬闸门）只在验收/发布检查点运行**：
   任务完工验收、里程碑判定（如 M3 开工前）、发布前复核、独立第三方复现。
2. **CI 不是持续集成灯**：不在工作中间当作状态仪表盘跑。工作中间想看进度，用
   `node scripts/tt-journey.mjs --workspace <目录>`（journey 投影）或
   `node scripts/summary-read.mjs`，它们不触发 S5 阻塞语义。
3. **检查点跑 CI 见红是预期行为**：S5 在严格口径（⬜/◐ 均未清零，见
   `plans/decision-s5-p0-semantics-20260920.md` 与 change record
   `cr-20260920T112945Z-a6244b0c`）下，进行中的 P0 会阻塞——这正是"修复没有完成
   证据 = 未清零"的独立实证纪律。检查点见红 → 修复完成并带证据后重跑，而不是改口径。
4. ◐ 行的卫生要求（无落点/收据引用按无证据 ⬜ 分类）同样只在检查点判定时生效，
   不要求工作中间维护。
