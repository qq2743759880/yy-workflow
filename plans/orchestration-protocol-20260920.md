# 编排协议 v1 — Owner 中继 / 编排者验收 / 外部平台执行（2026-09-20）

角色：**Owner**（用户，唯一人工闸，中继派单与报告 + 返工命令）｜**编排者**（本会话：派单、
独立验收、提交、推送）｜**执行者**（外部平台 agent：只做派单范围内的事）。

## 派单生命周期

```
编排者写 handoffs/T<N>-*.md → Owner 转发给执行平台 → 执行者施工（同一台机器、同一仓库）
→ 执行者在 test-reports/rebuild-20260920/<T<N>>/ 落 REPORT.md（自报，仅作线索，无证据效力）
→ Owner 回一句"T<N> 完工" → 编排者独立验收 → ACCEPTED（编排者 commit+push）/ REWORK-{n}（Owner 转发返工）/ ≥2 次返工升级 Owner 仲裁
```

## 盲测 task 约束（每份派单自动携带，执行者可见规则、不可见内容）

1. 派单 Prompt 只含：目标、规格指针（仓库内冻结文档）、允许写入白名单、禁止清单、纪律、
   STOP 条件、自报模板。**不含**验收探针、验收阈值、验收命令
2. 编排者验收探针在收到完工声明**之后**编写，来源 = 冻结规格本身；验收前不存在于任何执行者可读位置
3. 执行者自测 PASS 无证据效力（仅供其自纠）；验收结论只依据编排者复现
4. 规格溯源抽查点在验收时刻随机抽取（防预演、防针对实现定制验收）
5. 验收探针与验收报告归档 `test-reports/acceptance-20260920/<T<N>>/`，返工轮次 append-only 保留
6. 执行者禁读：`test-reports/acceptance-*/`、`.git/`；禁止 git commit/push（提交权在编排者）
7. 同一任务的验收探针跨返工轮次只增不改（防执行者第二轮针对第一轮探针过拟合——新增探针覆盖新发现）

## 批判性问题挖掘规则（编排者验收时强制执行，10 条）

1. **不采信**：报告任何 PASS/数字/哈希必须本会话复现；不可复现即驳回，不做任何"看起来对"豁免
2. **写入范围**：`git status` 与派单白名单逐一比对，多一个未授权文件即违规（无论内容好坏）
3. **哈希锚定**：交付文件 sha256 与执行者自报逐一对照，不一致即驳回
4. **反走捷径假设**：验收前先写 ≥3 条"执行者最可能的偷懒/作弊方式"（硬编码期望值、弱化断言、
   跳过边界用例、mock 掉真实 IO、只测 happy path），逐条设计检验并记录检验结果
5. **边界/负向实测**：非法输入、缺失字段、空文件、超长/中文路径、并发写——fail-closed 行为必须实测
6. **差分一致性**：重构/抽取类任务跑新旧差分，**错误路径同样差分**（process.exit、异常、超时分支）
7. **回归面**：regression-all 12/12 + validate-structure 0 警告 + 全部已有模块探针复跑
8. **规格溯源抽查**：随机抽 ≥5 个实现细节与冻结契约/施工方案逐条对照；发现未声明偏差从严（已声明偏差按方案 §偏差处理）
9. **报告诚实度**：报告的局限/偏差声明 vs 实测吻合度检查——少报从严、如实申报从宽
10. **分级登记**：发现按 P0（驳回+返工）/ P1（返工）/ P2（登记不阻塞）分级写入验收报告；
    编排者不得静默替执行者修代码

## 返工命令格式（REWORK-{n}）

```
REWORK-{n} for T<N>：
- 发现（分级 + 复现命令 + 期望行为 vs 实际行为）
- 允许写入（通常不变）
- 禁止：不得改动上一轮已 ACCEPTED 的内容
- 回报：同 REPORT.md 模板，追加"本轮修了什么/未修什么及原因"
```

## 执行者 REPORT.md 模板

```
# T<N> 执行报告
- 交付文件清单（路径 + sha256）
- 自测命令与输出（原样粘贴）
- 与规格的偏差声明（逐条；无则写"无"）
- [待补充] 项（保持待补充的，逐条）
- 局限与已知风险（诚实申报）
```
